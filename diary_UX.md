**Goals:**

1. Scalability of application for future studies  
2. Operational tolerance / support   
3. Research data protections   
4. Potential of user data outcome / accuracy   
5. Participant conversion / activation / retention / completion 

The 5 goals are user experience problems for the researcher and participant. 

**Recommendations**  
What is the risk tolerance? It’s an opportunity cost (Which recommendation will likely produce the value you are after, than not doing it)

1. Timeline starts at 00:00  
2. Collapse activities into a single list.   
3. Vertical timeline (mobile or both)  
4. Promote a single main action (happy path)  
5. Add label to main action (e.g. Add Activity)   
6. Stay in ‘add activity’ flow for adding activities  
7. Sleep carries over to the next day (show activity in prototype)  
8. Consolidate all secondary links and actions into a single sub menu  
9. Avoid destructive actions if possible   
10. Review step before actual submission  
11. Copy activities, not days   
12. Use form inputs for activity attribution: time, day, etc  
13. Simple language for all participants. No emojis. A simplified UI removes labeling and reduces instruction.   
14. Concurrent tasks (approx 3\)  
15. Accessibility  
16. Progressive enhancement \+ Graceful degradation (device determines user interface)  
17. If a Timeline-entry exists on the desktop, the default time should be more than 15 minutes. Increase the touch radius
